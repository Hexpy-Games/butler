## 구현 단위 I1: 원문 등록에서 실제 회상까지
첫 수직 구현은 의미 추출의 성공 여부와 무관한 원문 색인이다. 기존 원문 구간별로 정확한 UTF-8 내용을 저장하는 source text projection과 Unicode 검색 postings를 ingestion의 원문 등록 트랜잭션에서 함께 만든다. 검색 postings는 원문으로 재생성 가능하며 원문/검색 여부의 상태를 모델 결과에 묶지 않는다.
새 schema: memory_source_text(id INTEGER PK,source_id UNIQUE/FK→memory_chunk_sources.source_id,text,text_hash); memory_source_terms(term,source_key INTEGER FK→memory_source_text.id,PK(term,source_key),WITHOUT ROWID). text_hash는 구간 텍스트 SHA256이고 기존content_hash(전체 scalar)와 구분한다. 원문 변형 금지, 코드포인트/byte 경계를 검사한다. 검색어는 기존Unicode NFC/casefold를 사용한 grapheme1/2/3-gram; 원문은 그대로 둔다. 분할자식은 새로 색인하고 부모 원문/근거는 유지한다. 오래된revision/격리/제외/프로젝트/세션/시각 필터를 후보 LIMIT 전에 적용한다.
public ingestConversationMemory 및 typed ingest가 쓰고, recallSourceBackedMemory가 같은 검색 경로에서 사용한다. 기존 의미그래프·벡터 결과와 episode 단위로 합쳐 중복을 제거한다. 추출된요약이 없는 원문도 원문 발췌로 반환하며 모델 해석인것처럼 합성 요약을 만들지 않는다. 구조적 증거 없는 원문 결과에는 unclassified_source qualification을 붙인다. event-time 질의에는 발화시각을 사건시각으로 대입하지 않는다. 새 엔티티/주장/관계 스키마는 다음 수직단위에서 기존소유자를 제거하며 이 단계의 존재가 전체 신규구조완료를 뜻하지 않는다.
범위 검증: 모델호출0인 public ingestion→recall, 실패상태에서도 원문조회, 여러언어/1글자/결합문자 보존, 범위 밖 source 제외, 재등록중복 방지, 분할 후 조회. 로컬 실제DB 경로를 이용하고 테스트전용 검색경로는 만들지 않는다. 통계: source/span coverage와 postings 크기, 신규모델호출0을 기록한다.

# 원문 중심 그래프 메모리 개선 — 분리된 설계 초안

## 최신 사용자 결정과 범위
기존 W-MEMORY-RECOVERY-MULTILINGUAL/T-MEMORY-RECOVERY-ROLLOUT 및 운영 복구는 기존 계획으로 계속한다. 이 개선은 독립 Work로 관리하며 기존 복구의 추가 완료 조건이 아니다. 현재 등록 범위는 설계 초안, 실행 단계, 향후 벤치마크 기준이다. 구현·이전·실제 모델 벤치마크·운영 전환은 아직 실행하지 않았다.
구형 스키마 호환 계층과 이중 쓰기는 요구하지 않는다. 필요한 최종 스키마를 설계하고 기존 데이터를 일회 이전한다. 재사용 대상은 원문·근거·유효 추출 결과·동일 텍스트/분할/모델의 임베딩이다.

## 목표와 실제 경로
기존 public ingestion → 원문 등록 → projection → recall_memory 경로 안에서 구현한다. 별도 제품 메모리 서비스나 테스트 전용 진입점으로 대체하지 않는다. 기존 복구 worktree, 운영 DB, generation, 실행 프로세스와 모델 정책을 개선 실험에서 변경하지 않는다. 구현 시 독립 worktree 및 독립 데이터 디렉터리를 사용한다.

## 최종 구조의 책임
- 원문/구간: 원문을 변경하지 않고 발화자·시각·대화 위치·해시 및 정확한 근거 범위를 프로그램이 저장한다.
- 엔티티/별칭: 정체성과 원어 이름을 저장한다. 언어 간 동일성이나 대명사 해석은 추정 연결이며 이름만으로 자동 병합하지 않는다.
- 언급: 직접 문자열 등장과 추정된 지시 대상을 구분한다. 기존 entity_mentions 전체를 직접 문자열 등장으로 승격하지 않는다.
- 기억: 주장·요청·질문·선호·관찰을 담되 프로그램이 확인한 출처, 모델의 의미 분류, 유효시점/충돌/정정 상태를 분리한다.
- 관계: 의미 관계는 해당 관계를 주장한 기억과 원문 근거를 가진다. 함께 언급됨을 소유/인과/완료 관계로 바꾸지 않는다.
- 근거와 이력: 추출 출처, 뒷받침, 반박, 정정의 역할을 구분한다. 같은 출처를 재인용한 버틀러 응답은 독립된 증거로 세지 않는다.
- 검색/캐시: 재생성 가능한 파생 데이터이며 의존 원문/기억의 버전을 기록한다.

## 처리 계약
원문 보존과 검색 색인 준비는 의미 추출 A 및 기존 기억 연결 B와 독립시킨다. A의 유효한 원문 결합 결과는 B 실패에도 보존·검색한다. B 대상이 없거나 애매하면 새로운/임시 정체성으로 보존하고 추정 연결만 보류한다. 무효 근거는 저장을 거부하되 독립된 원문 검색까지 실패시키지 않는다.
모델은 짧은 입력별 번호와 의미만 출력하며 프로그램이 영구 ID, 원문 위치, 출처, 버전을 채운다. 입력 허용 번호와 교차 소속을 검사한다. 이것이 원문의 의미까지 검증한다고 주장하지 않는다.
사용자 발화·버틀러 보고는 모델 분류와 무관하게 실행 관찰로 승격할 수 없다. 도구 기록도 실제로 관찰한 범위와 시점만 나타낸다. 조건 any/all/not 등 이미 보존되는 의미를 단순화 과정에서 잃지 않는다.

## 검색과 수정
전체 데이터의 어휘/별칭/다국어 벡터로 시작점을 찾고 언급·의미 관계·대화 문맥을 제한적으로 확장한 뒤 원문을 반환한다. 최신200개로 후보 모집단을 자르지 않는다. 원문·발화자·시각·해석 종류·충돌을 함께 반환한다. 현재 기능 가능 여부는 가능하면 실제 상태를 확인하고 없으면 마지막 관찰 시점을 밝힌다.
정정은 원문을 덮어쓰지 않고 변경 관계로 남긴다. 오염 원문 제외는 그 원문에만 의존하는 해석·관계·요약·캐시를 함께 제거/재구성한다. 독립된 정상 근거는 보존한다. 변경된 근거의 오래된 캐시는 사용하지 않는다.
원문은 어떤 언어든 보존한다. 검색용 정규화 키와 임베딩을 별도로 관리하며 번역으로 원문을 덮어쓰지 않는다. 모든 언어의 검색 정확도가 동일하다고 보증하지 않는다.

## 비용과 이전
최종 스키마와 이전 매핑을 먼저 확정한다. 그대로 이전/기계적 변환/추가 의미 판단 필요 항목을 스크립트로 집계한다. 저장된 단계 응답과 최종 출력을 재사용하며 일괄 재추출을 기본값으로 두지 않는다. 복원 불가능한 의미는 분류 미확정으로 보존하고 검증된 관찰로 만들지 않는다. 무효 근거를 유효하다고 이전하지 않는다.
이전은 스냅샷에서 새 스키마 구축 → 원문/근거 보존 및 검색 검증 → 최종 변경분 반영 → 별도 운영 전환 단계다. 구형 DB는 백업일 뿐 상시 호환 경로로 사용하지 않는다. 예상 개발 작업량12~20시간은 미측정 추정이며 기존 복구시간과 별도다. 추가 모델 비용은 결손 집계 전 미확정이다.

## 향후 벤치마크 계약
등록 시점 기준 코드 SHA: 90c31ae30ffa4e98c35eabff94e55c77a692e3e1. 이는 r58 시점 표시이며 최종 비교 기준이 아니다. 기존 복구의 최종 기준 SHA와 완료 데이터의 일관된 읽기 전용 스냅샷을 나중에 동결한다. 현재 실행 중 DB를 완료된 고정 기준선이라고 부르지 않는다.
동일 원문/질의/범위/모델/effort를 사용하며 원문과 후보 자료, 모델 입력 계약 차이를 manifest에 기록한다. 먼저 저장된 동일 추출 결과 재생으로 저장·검색 변경을 비교하고, 의미추출 변경 효과는 별도의 실제 A→B 전체 실험으로 구분한다. 기존/신규 추출을 비교할 때 기준선 응답이 새 계약의 출력이었다고 간주하지 않는다.
질의와 기대 근거는 결과를 보기 전에 고정한다. 관계 개수 증가가 아니라 목표 원문 회상, 출처 구분, 요청의 사실 오인, 조건 보존, 정정/오염 제외, A/B 실패 시 원문 접근을 본다. 다국어와 모호한 정체성 대조 사례를 포함한다. 미래 모델 실험은 조건별 모델당 전체처리3회 기준이며 이번에는 호출하지 않는다.
총 입력/출력/캐시 토큰, 호출·재시도, 전체 처리시간, 검색 지연과 cold/warm 조건, 이전 누락·근거 단절·임베딩 재사용을 기록한다. 소수 반복 평균/범위를 보고하며 p95나 일반 품질 보증으로 과장하지 않는다. 모델 오분류를 의도적으로 주입해 출처 승격 방지를 확인한다.

## 실행 단계와 현재 검토
1. 스키마 상세화·필드/FK·이전 매핑·원문 검색 준비 상태 정의 및 보완량 집계.
2. 독립 환경에서 실제 ingestion→recall 수직 구현, 이전, 정정/캐시 검증.
3. 고정 데이터 비교와 결과 리뷰. 운영 전환은 이 결과와 별도 적용 결정 이후다.
이번 리뷰: 기존 복구와 완료 조건 분리, 일괄 재추출 배제, 구형 스키마 호환 비요구, 모델 오류와 코드 보증 구분, 벤치마크 보류를 확인했다. SQL/세부 필드·실행 예산은 1단계 산출물이며 구현 준비 완료라고 주장하지 않는다.
