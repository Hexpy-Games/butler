# 원문 중심 메모리 그래프 구현 결과

## 완료 범위
I1~I4의 개발과 격리 데이터 이전 검증을 완료했다. 실제 진입점은 기존 `ingestConversationMemory → advanceNextMemoryProjection → recallSourceBackedMemory`이며, 요약 캐시도 기존 writer/reader를 사용한다. 운영 복구는 별도 작업 `01a0961d-8382-79a1-ae02-7b1054086930`이 담당한다. 유료 모델별 비교와 운영 세대 전환은 사용자가 분리한 후속 범위다.

## 구현과 논리 리뷰
1. 원문 등록 트랜잭션에서 Unicode 색인을 만든다. A/B 실패가 원문 검색 가능성을 없애지 않는다. 전체 모집단에서 범위·활성 상태·시각을 먼저 적용하며 최신 200개로 자르지 않는다. 질의 전체가 원문에 그대로 등장하면 연관 개념만 일치하는 결과보다 먼저 반환한다.
2. 공통 노드, 기억 내용, 추출 근거, 직접/추정 언급을 분리했다. `memory_nodes.properties`와 구형 혼합 테이블은 최종 DB에 없다. 요청은 독립 발화 종류이며, 언급의 byte 범위는 해당 source span 안의 UTF-8 위치다. 원문을 번역하거나 정규화해서 덮어쓰지 않는다.
3. A 검증 후 필수 저장 콜백을 통과해야 B를 호출한다. window와 원문 입력 해시로 A 저장을 검증하고, immutable 내용과 window에 묶인 ID를 사용한다. B 실패/재개에서 유효 A를 다시 추출하거나 삭제하지 않는다. 미완료 A 노드는 다른 B의 과거 후보에서 제외한다.
4. B의 동일 대상 판정은 근거가 있는 `identity_match` 연결이다. 기존 노드에 새 출처를 합쳐 쓰지 않는다. 지원되는 claim 재사용도 `same_claim` 탐색 연결로 보존하며, B의 현재 모델 입력은 대상 동일성 및 명시적 정보 정정만 요청한다. 일반적인 동일 주장 판정용 추가 모델 호출은 만들지 않았다. B가 구형 문장의 일부를 보정하면 A를 보존하고 새 기억과 `refines` 이력을 추가한다. 정정에는 현재 발화와 구형 문장의 근거를 함께 저장한다.
5. 프로그램이 canonical role/source_kind에서 출처를 결정한다. 모든 추출 기억은 `authority=model_interpretation`이다. 사용자 발화와 버틀러 보고는 실제 실행 관찰로 승격되지 않는다. 검색은 해석·발화 종류·출처와 실제 상태 확인 필요 여부를 반환한다. `recorded`는 저장된 해석이며 사실의 현재성을 보증하지 않는다. 반환 근거가 빠진 해석/조건을 최소 응답에 남기지 않는다.
6. 정정/만료가 원문을 삭제하지 않는다. 원문은 과거 자료로도 회상할 수 있고, 모델 해석의 상태를 구분한다. 제외된 source는 그래프·검색·캐시에서 차단한다. 캐시는 현재 revision, canonical 원문 및 모든 의존 출처를 검증하고, 읽을 때도 출처와 해석 권한을 표시한다. 조건 any/all/not 구조와 수동 동일성 정정 이력을 유지했다.

## 실제 데이터 이전
명시적인 offline CLI가 SQLite 스냅샷을 새 파일로 복사한 후 트랜잭션으로 변환한다. 원본 DB에 쓰지 않으며 목적지가 이미 존재하면 거부한다. 실패하면 변환 트랜잭션을 되돌린 복사본이 남는다. 데이터 변환은 완료 추출 결과/속성을 재사용하고 추가 모델을 호출하지 않는다. generation의 신규 schema_version과 DB의 source_graph_schema는 3이다. 운영 배포 시에는 해당 generation의 기존 임베딩 자산과 설정을 함께 유지해야 한다. 이 CLI는 운영 세대 전환 도구가 아니다.

검증 복사본: `/tmp/butler-memory-source-graph-20260913/normalized-final.sqlite`.

- 노드 5,233개, 기억 3,414개, 추출 근거 5,506개, 언급 2,199개, 원문 1,322구간.
- 직접 언급 1,710개와 추정 언급 489개를 구분했다. 직접 언급의 원문 byte 범위 불일치 0개.
- 구형 목표/발화 종류를 확정할 수 없는 605개는 unknown으로 보존했다. 서로 다른 출처가 이미 합쳐진 7개는 mixed로 보존했다.
- 원문 레코드, projection window 1,026개, 시도 이력 2,885개, 벡터 작업 6,892개, 관계 3,176개, 관계 근거 3,313개의 전후 전체 행 해시가 같다. 원래 노드/관계 ID도 보존했다.
- FK 오류 0개, 구형 entities/mentions/aliases 테이블 및 호환 view 0개, 추가 모델 호출 0회.
- 최종 CLI 한 번 실행은 복사 및 검증을 포함해 74.24초였다. 앞선 변환 본체 측정은 56.82초였다. 배포 환경의 예상 시간이 아닌 로컬 관찰치다.

## 실제 데이터에서 발견하고 수정한 검색 문제
episode→node, source→node, claim→edge 색인이 없어 근거 집계가 후보마다 반복 스캔했다. 별칭 빈도의 모집단도 400개 gram 묶음마다 재구성했다. 관련 색인을 추가하고 모집단을 한 번 구성하도록 변경했으며 기존 IDF 식은 유지했다.

같은 고정 원문 3건의 질의에서 수정 전 29.19/8.33/28.43초 동안 원문을 반환하지 못했다. 수정 후 1.20/0.50/0.51초에 세 건 모두 정확한 원문을 반환했다. 단순 fixture의 통과만으로 완료 판정하지 않고 실제 복사본에서 확인했다. 이 수치는 부하/캐시를 통제한 모델 품질 벤치마크나 p95가 아니다. 복사본은 아직 복구 진행 중인 세대의 스냅샷이므로 결과 coverage는 partial로 유지했다.

## 검증과 잔여 항목
핵심 공개 경로, 다국어/오래된 원문, A/B 실패·재개, 의도적 오분류, 출처 분리, 실제 캐시 제외, OR 조건, 정정·회상 범위·직렬화·벡터 재사용 검사를 실행했다. 최종 핵심·유지보수 묶음 61개(375 assertions), 별도 수동 동일성 CLI 1개(84 assertions)가 통과했다. 합계 62개이며 중복 집계하지 않았다. backend typecheck와 변경 파일 lint(오류 0), diff 검사도 통과했다.

추가로 넓힌 기존 T3 묶음의 4개 실패는 변경 전 I1 커밋 `cea4ff77269ddc0730415956e1a0dfaad73b8558`을 독립 디렉터리에 펼쳐 동일하게 재현했다. 과거 날짜를 고정한 재시도, 현재보다 큰 구형 window 가정, vector 저장 중단 직후 상태 불일치, graph 완료 window 없이 summary만 주입한 cache fixture 검사다. 변경 전 재현은 이번 개선의 회귀가 아니라는 근거이며, 모든 실패가 무해하다는 근거는 아니다.

### 후속 검사 보정 — 2026-09-13
사용자 지시에 따라 1·2·4번의 테스트 구성만 수정했다. 프로덕션 소스, 운영 서비스, 복구 프로세스 및 데이터는 변경하지 않았다.
- 1: 등록된 `next_attempt_at`의 1ms 전에는 작업을 가져올 수 없고 해당 시각에는 두 번째 시도를 시작한다. 이후 실패 이력과 다음 재시도 시각 보존까지 검사한다.
- 2: 현재 단일 원문 window에 공급자의 입력 용량 초과를 두 번 주입하여 실제 `advanceNextMemoryProjection`의 재귀 분할을 실행한다. 최소 조각 크기를 충족하는 다국어 입력을 사용하고 UTF-8/grapheme 경계, 원문 연결 복원, 순서 및 실제 완료 결과의 재등록 후 보존을 검사한다. 초기 테스트 입력은 최소 분할 크기보다 작아 용량 초과로 종료됐으며, 실제 상수에 맞춰 준비 분량을 수정했다.
- 4: 실제 의미 추출·근거 검증·완료 저장을 거친 첫 요약에 파일 쓰기 실패를 주입한다. 재시도 시각과 경로 복구 후 내용을 확인하고, 두 번째 window 완료로 새 요약을 반영한다. 캐시 writer 재실행과 원문 재등록 전후 파일 내용이 동일한지 검사한다.

세 검사 3/3 통과(43 assertions), T3 파일 전체 10/11 통과(79 assertions). 남은 실패는 3번 벡터 완료 표시 중단 시 `pending` 기대에 `running`을 반환하는 기존 사례다. 이후 회수·재개 및 중복 임베딩 방지는 이 실패한 검사에서 실행되지 않았으므로 별도 확인이 필요하다. 테스트는 로컬 공급자 대체 응답을 사용하며 유료 모델 호출은 0회다.
