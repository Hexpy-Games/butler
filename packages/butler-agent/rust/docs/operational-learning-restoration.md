# Operational learning restoration: investigation and approval design

Date: 2026-10-02. Branch: `codex/oplearn-restore`. Inspected Rust baseline: `09ffe9679`.
Design only; no production changes, builds, live data reads, or model calls.

## Recommendation and purpose

Restore a supported model-to-feedback ingress and a real consolidation destination. Keep explicit durable instructions/preferences in **지침 / Instructions**; put situational corrections and source/tool complaints in **최근 피드백 / Recent feedback**. The buffer exists to change the next relevant turn before heavy consolidation can decide what deserves durable storage. Today the supported remember tool writes durable instructions immediately; it does not supply that intermediate stage.

For artifacts, recommend option C below: use existing published artifact registrations and stored files, with a project-scoped recall consumer. Do not bulk-ingest the reported 13,312 files into Box. This is a proposed amendment to the Box pipeline spec, requiring owner approval, rather than a claim that the existing implementation satisfies it.

Inputs read in full: `/home/yeonw/workspace/bench/specs/cognition-operational-learning.md` (SPEC-COGNITION-OPERATIONAL-LEARNING) and `cognition-box-memory-metadata.md` (SPEC-COGNITION-BOX-MEMORY-METADATA). Operational learning prescribes feedback → immediate scoped application → scheduled routing, with feedback, Box evidence, memory observations and source quality feeding later know-how. Box prescribes save → tiny origin event → asynchronous enrichment. Those contracts were only partly implemented in the available history.

## Smallest feedback restoration contract

### Ingress and immediate application

Recommend a separate native **record_user_feedback** tool, available through the supported chat catalog/discovery, rather than extending update_explicit_memory while its correct/forget contract is changing. Reuse storage/lease/parser, not the abandoned continuity machinery. Its schema takes compact faithful text, scope global/project/session, category, target_ref and retention class; runtime binds actual owner/project/session, message/turn/tool ids and an idempotent operation id. The model cannot choose filesystem paths, foreign project ids, applied status, or arbitrary promotion ids. Return a stable feedback handle and recorded/pending/failed status; never claim durable capture on failure.

Model instructions: save clear durable instructions and preferences as 지침 with the existing tool; record situational correction or tool/source dissatisfaction as Recent feedback before answering; apply it now and on the next matching turn. Explicit “always/앞으로” preferences go directly to Instructions, including a clear permanent source prohibition. A complaint like “that result was poor” is a quality signal, not authority to ban every source. Resolve “that source” from verified current-session tool evidence. Broad ambiguous target/scope or safety/privacy conflicts produce one unrouted needs_clarification record and one narrow immediate question; they cannot become active policy before clarification.

Feedback capture must not be gated behind work-plan acceptance or an unrelated pending approval. It is an explicit user-authorized local cognition mutation with data-authority checks. Duplicate calls replay the same handle; identical in-scope existing Instructions are linked as already represented instead of adding another instruction. A genuine correction to a saved Instruction references its handle and uses the in-flight replaces/tombstone service when promoted; this proposal does not implement that service again.

### Scope, lifecycle and conflict

Store the spec's parseable blocks at `$BUTLER_DATA/cognition/feedback/feedback.md`, preserving unknown fields and invalid records for inspection. Preserve legacy labels when reading; new entries encode owner scope as global/project:<bound-id>/session:<bound-id>, separately from target/category. No implicit widening to global. Tool/source/style/knowhow labels describe relevance, not ownership. Global crosses chats/projects; project crosses chats in that project; session applies only to that chat. Global is owner-local; no multi-user namespace is introduced.

Proposed defaults: situational correction/quality signal **ephemeral, 7 days**; unresolved cross-turn correction **working, 90 days**; explicit pinned feedback no automatic expiry; resolution receipts **audit**, manual prune only. Store retention_class as a preserved field and materialize expires_at on capture. session_only ends on explicit session closure or 24 hours, whichever comes first; closing a tab is not session termination. At turn assembly, expired entries cease applying immediately; the existing daily/manual pass records discarded with expiry reason before clearing. No expiry timer. Pinned feedback cannot be silently dropped because know-how is unavailable. The 7/90-day defaults come from the spec; classification into defaults is a proposed owner decision.

Prompt explicitly states: safety/privacy > current user instruction > active applicable feedback > project Instructions/capsule > global Instructions/profile > know-how > defaults. Within equal ownership/target, newest explicit correction wins; supersedes/conflicts are recorded. Relevant quality signals advise revalidation/routing, not unsupported factual conclusions. Sensitive raw feedback needs the spec's provider gate; secret raw text stays local. Reports/metrics contain ids/counts/reasons, never raw text.

Keep recent_feedback in dynamic live_configuration, after the stable static prefix; content changes invalidate its live hash (`butler-runtime/src/context/prompt/cache.rs:10`). Stable ordering and revision-based snapshots avoid incidental cache churn. Existing 12-entry/500-character cuts can hide a prohibition: remove silent semantic truncation and include complete applicable entries. Do not cap active policy to pass a latency budget. Snapshot partitions by scope and indexes target ids; load/update only changed state, with no directory/full history scans at turn admission. If policy cannot fit the existing prompt budget, use existing explicit context-overflow handling, never quietly omit it. UI paging may be bounded; behaviour must remain complete.

### Lease contention, durability and scheduling

All feedback-file changes and promotion commits use the existing consolidation lease plus data-authority guard; `feedback_buffer/operator.rs:155` is the reuse point. Atomic temp/replace, idempotent ids, no blocking filesystem I/O on async workers. Consolidation already releases the lease around phase computation (`butler-memory/src/cognition/consolidation/engine.rs:1`); keep commits short and yield to foreground changes at checkpoints.

A busy lease must not lose feedback or block admission. Add a typed pending feedback mutation to the existing durable turn/tool-operation journal, then project it under the lease on the existing event-driven work path. The pending receipt participates in a scoped in-memory prompt overlay immediately after its durable commit; canonical file plus pending operations are deduplicated by operation id. Startup recovers these receipts into the overlay before the executor is ready. This journal integration is required new work, not an assertion that today's operator_add already queues: today it returns MemoryWriteBusy (:167). No new polling loop, timers, queue files, or idle full-file reads. The journal uses its existing storage transaction; every canonical cognition-file mutation remains under the consolidation lease.

Pending receipt persistence and reset generations must be ordered with prompt snapshot publication. A turn admitted before the correction commits cannot retroactively change; every later scoped turn sees it, including queued follow-ups. Failure to persist returns failed and no “saved” acknowledgement. No write of either receipt or canonical data into a refused legacy root: validate data authority before any side effect, not after making a directory. Recovery must obey the same rule.

### Consolidation without restored know-how

Extend the existing daily/manual triage phase, not a new scheduled job. Retain current rate-limit preflight (<10% defers heavy work), checkpoint/resume and quiet-window policy. Read a stable feedback revision; plan outside the lease, validate that revision and commit destinations/resolutions under the lease. A crash after destination write but before resolution replays by feedback-id-derived operation id. Only resolve applied after the destination commit succeeds; new corrections arriving during planning remain active.

Routing is explicit and conservative: an unambiguous reusable user mandate promotes to Instructions; a consented stable personal preference/profile fact uses the existing profile candidate path and resolves only after accepted durable profile commit; project mandates preserve project scope. Transient/expired/withdrawn/duplicate feedback is discarded with reason and destination link where applicable. A quality signal does not generate a durable instruction by itself. Record review evidence and retain it until expiry; keep promotion_target source_quality/knowhow as a deferred hook. A clear continuing source restriction can promote to scoped Instructions today, without a know-how service. Do not label deferred know-how as applied, promote strategy automatically, or erase a pinned complaint.

No opportunistic transcript audit mining. Model-assisted classification, if needed, runs only in the heavy pass with privacy gates and reviewable ids; deterministic idempotency/deduplication/lifecycle is runtime-owned. Durable correct/forget handles and tombstones remain owned by the in-flight Instructions work; recall ranking and alias storage remain owned by their existing work.

### User control and copy

Add one kind to the planned Settings Memory page: **최근 피드백 / Recent feedback**. Show compact text, scope, expiry, active/needs clarification/promoted/discarded state and a destination link to Instructions/profile. Reuse page inspect/edit/delete/reset controls; edits preserve provenance and supersede the old revision. Per-kind disable excludes feedback from subsequent prompts without deleting audit receipts; re-enable must still respect expiry. Do not build a separate settings page in this slice.

Reset records explicit user deletion and advances a reset generation under the same serialization contract. Clear active and pending feedback, invalidate snapshots, and prevent an already-running consolidation plan or recovered pending operation from resurrecting it. Keep raw-text-free deletion receipts only; manual audit prune is separate. Reset does not delete promoted Instructions/profile; their own reset kinds handle those. Integration with Memory “free up space” is limited to resolved payloads/audit policy, never silent removal of active policy. Short acknowledgement: “반영했어요.” / “Feedback saved.” Do not expose internal terms rule, 규칙 or Steward in product copy.

## Owner decisions (concrete alternatives)

1. **Separate record_user_feedback tool (recommended), or add feedback kind to update_explicit_memory?** Separate tool keeps durable Instructions correct/forget independent and makes classification explicit.
2. **Durable mandates/preferences straight to Instructions, situational corrections/complaints to Recent feedback (recommended), or all explicit corrections/preferences through feedback first?** The first matches the historical distinction and avoids an unnecessary temporary stage for clear durable requests.
3. **Ephemeral 7-day complaints, working 90-day unresolved corrections, explicit pinning (recommended), or make all non-session feedback working 90 days?** Neither option silently expires pinned feedback; session_only remains end/24h and disposal is recorded.
4. **Project artifact recall on existing registrations, option C (recommended), or full Box events/manifests/worker plus recall now, option A?** C deliberately amends the Box architecture; B is a cheaper retirement option only if model retrieval is not wanted.
5. **Show and reset Recent feedback as its own Memory kind (recommended), or combine it with Instructions reset?** Separate reset preserves promoted Instructions and makes temporary feedback understandable.
