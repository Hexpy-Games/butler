**설정 → 보안**에서 **다른 컴퓨터에서 접속 허용**을 켜면 같은 네트워크의 다른 컴퓨터가 브라우저로 Butler에 접속할 수 있습니다. 접속하는 브라우저에는 연결 코드를 입력합니다.

<Notice tone="info">
  **보안** 설정은 Butler가 실행 중인 호스트 컴퓨터에서만 바꿀 수 있습니다. 다른 컴퓨터에서 열면 **호스트 컴퓨터에서만 사용할 수 있습니다.** 메시지가 표시됩니다.
</Notice>

## 접속 허용하기

**다른 컴퓨터에서 접속 허용**은 처음에 꺼져 있습니다.

<Steps>
  1. 호스트 컴퓨터에서 **설정 → 보안**을 엽니다.
  2. **원격 접속**의 **다른 컴퓨터에서 접속 허용**을 켭니다. 앱을 다시 시작하지 않아도 바로 적용됩니다.
  3. 아래에 나타나는 **접속 주소**에서 쓸 주소 옆의 **주소 복사**를 누릅니다.
</Steps>

**접속 주소**는 접속을 허용한 동안에만 나타나며, 이 컴퓨터의 네트워크 주소를 `http://` 주소로 보여 줍니다. 표시할 주소가 없으면 **네트워크 주소 없음**이 나옵니다. 이때는 [문제 해결](/help/troubleshooting/#접속을-허용했는데-주소가-표시되지-않습니다)을 참고합니다.

## 다른 컴퓨터에서 접속하기

<Steps>
  1. 다른 컴퓨터의 브라우저에서 복사한 접속 주소를 엽니다.
  2. **Connect to Butler** 화면의 **Connection code**에 연결 코드를 입력합니다.
  3. **Connect**를 누릅니다.
</Steps>

코드가 맞지 않으면 **That code is not valid.** 메시지가 표시됩니다. 연결 코드는 호스트 컴퓨터의 **설정 → 보안**에서 확인합니다.

### 호스트 컴퓨터의 브라우저로 열기

호스트 컴퓨터에 [Butler Agent CLI](/help/advanced/agent-cli/)가 있으면 `butler open`을 실행합니다. 연결 코드를 입력하지 않아도 이 컴퓨터의 브라우저에서 실행 중인 Butler가 열립니다.

```bash
butler open
```

## 연결 코드 관리

**연결 코드**의 **코드** 칸에는 코드가 가려진 채로 표시되고, 그 아래에 발급 날짜가 나옵니다.

- **보기** — 코드를 표시합니다. 표시하는 동안에는 **숨기기**로 바뀝니다.
- **복사** — 코드를 클립보드에 복사합니다.
- **재발급** — 새 코드를 발급합니다. **연결 코드를 재발급할까요?** 확인 창에서 **재발급**을 누르면 적용됩니다.

재발급하면 이전 코드로 접속한 다른 컴퓨터의 연결이 끊깁니다. 다시 접속하려면 다른 컴퓨터에서 새 코드를 입력합니다.

## 허용 호스트

직접 운영하는 터널이나 리버스 프록시로 접속하려면 그 이름을 허용 호스트로 등록합니다. 허용 호스트는 **설정 → 보안** 아래의 **고급**에 있습니다.

<Steps>
  1. **고급**에서 **터널·프록시용 허용 호스트**를 눌러 펼칩니다.
  2. **호스트 이름**에 터널이나 프록시가 쓰는 이름(예: `butler.example.com`)을 입력합니다.
  3. **추가**를 누릅니다.
</Steps>

등록한 이름 옆의 삭제 버튼을 누르면 목록에서 뺍니다. 호스트 이름이나 IP 형식이 아니면 **호스트 이름이나 IP를 입력하세요** 오류가 표시됩니다.

허용 호스트로 접속해도 연결 코드를 입력해야 합니다. 터널과 프록시의 보안은 직접 관리합니다.

## 주의 사항

<Notice tone="warning" title="믿을 수 있는 네트워크에서만 허용합니다">
  같은 네트워크에서 연결 코드를 아는 사람은 누구나 Butler에 접속할 수 있습니다. **다른 컴퓨터에서 접속 허용**은 믿을 수 있는 네트워크에서만 켭니다.
</Notice>

## 헤드리스 / WSL / 서버

서비스가 실행 중인 컴퓨터의 터미널에서 원격 접근을 켠 뒤 연결 코드를 읽습니다. 기본값은 꺼짐입니다.

```bash
butler start
butler remote enable
butler remote code
```

다른 컴퓨터에서 `http://HOST:PORT`를 열고 코드를 입력합니다. `HOST`는 서버 또는 WSL에 연결되는 주소이며, `PORT`는 `remote enable`이 출력한 LAN URL의 포트입니다. 연결 코드는 로컬 터미널에만 출력됩니다. 코드는 비공개로 다루며 로그에 저장하지 않습니다.

```bash
butler remote status --json
butler remote code --rotate         # 확인 후 발급; 기존 코드 무효화
butler remote code --rotate --yes   # 확인 생략
butler remote hosts add 192.0.2.10
butler remote hosts remove 192.0.2.10
butler remote disable
```

WSL 포트 전달이나 프록시가 다른 호스트를 제시하면 해당 이름 또는 IP를 `allowedHosts`에 추가해야 합니다. 예를 들어 Windows 호스트 IP로 전달한다면 `butler remote hosts add WINDOWS_IP`를 실행합니다. 포트 전달과 방화벽은 별도로 설정합니다. 서비스가 꺼져 있으면 명령은 `butler start`를 안내하며 자동으로 시작하지 않습니다.

`remote status`는 바인드 주소, LAN URL, 주소별 바인드 오류, 허용 호스트, 마스킹된 코드와 생성 날짜를 보여 줍니다. `code --json`은 전체 코드를 포함하므로 로컬에서만 다룹니다. 코드 교체는 기존 코드와 브라우저 세션을 무효화합니다.

현재 `butler config get app.port`는 App 포트를 읽지 못합니다. 실제 설정은 데이터 폴더의 `gateways/app.json` 안 `config.port`에 있으며, 변경은 재시작 후 적용됩니다. 설정 파일은 실행 중인 서비스를 중지한 뒤 수정합니다.
