원격 접근은 기본으로 꺼져 있습니다. Butler를 실행하는 컴퓨터에서 켠 뒤, 다른 컴퓨터의 브라우저를 일회용 코드로 연결합니다. 앱에서는 **설정 → 보안**에서, 앱 없이 쓸 때는 CLI로 관리합니다. 보안 관리에는 로컬 클라이언트와 로컬 관리자 자격 증명이 필요합니다. 다른 컴퓨터에서 연 화면의 **설정 → 보안**에는 **호스트 컴퓨터에서만 사용할 수 있습니다.** 메시지가 표시됩니다.

## 앱에서 기기 연결하기

<Steps>
  1. Butler를 실행하는 컴퓨터에서 **설정 → 보안**을 엽니다.
  2. **다른 컴퓨터에서 접속 허용**을 켭니다. **접속 주소**에 다른 컴퓨터에서 열 주소가 표시됩니다.
  3. **기기 연결**을 누릅니다. **코드**에 8자리 코드와 남은 시간이 표시됩니다.
  4. 다른 컴퓨터의 브라우저에서 접속 주소를 열고 연결 폼에 코드를 입력합니다.
  5. 연결되면 **기기를 연결했어요**가 표시되고, **연결된 기기** 목록에 그 기기가 나타납니다.
</Steps>

- 코드는 60초 동안 한 번만 쓸 수 있습니다. 만료되면 새 코드를 자동으로 발급합니다.
- 입력을 세 번 실패하면 코드가 무효화됩니다. **실패가 반복돼 새 코드를 발급했어요**와 함께 새 코드가 표시됩니다.
- **연결된 기기**에는 기기 이름, IP 주소, 마지막 접속 시각이 표시됩니다. **연결 끊기**는 그 기기의 연결을 끊고, **모두 끊기**는 확인 창을 거쳐 모든 기기의 연결을 끊습니다.

항목별 설명은 [설정 레퍼런스](/help/settings/#보안)를 참고합니다.

## Headless / WSL / 서버

```bash
butler start
butler remote enable
butler remote pair
```

다른 컴퓨터에서 `butler remote enable`이 보여 주는 LAN URL을 열고 연결 폼에 8자리 코드를 입력합니다. 서버 주소 또는 WSL로 전달되는 주소를 사용합니다. 방화벽과 포트 전달은 별도로 설정합니다. 신뢰하는 네트워크에서 사용합니다.

`pair`는 브라우저를 열지 않고 터미널에서 계속 실행됩니다. 코드는 60초 동안 한 번만 사용할 수 있습니다. 입력을 세 번 실패하면 무효화됩니다. 터미널에 남은 시간이 표시되며, 만료되거나 무효화되면 새 코드를 자동 발급합니다. 기기가 연결되거나 Ctrl-C를 누르면 종료됩니다. 새 코드를 발급하면 이전 코드는 무효화됩니다. 짧은 코드는 폼 POST로만 제출할 수 있으며 URL로는 사용할 수 없습니다. 터미널 출력을 비공개로 유지하고 로그로 남기지 않습니다.

```bash
butler remote status --json
butler remote devices
butler remote devices --json
butler remote devices --revoke DEVICE_ID
butler remote devices --revoke-all
butler remote disable
```

기기 목록은 재시작 후에도 유지됩니다. 기기를 해제하면 쿠키가 즉시 거부되고 실시간 이벤트 스트림도 닫힙니다. 모든 기기를 해제해도 로컬 bearer 인증은 유지됩니다. `butler open`은 이 컴퓨터의 일회용 링크를 열고 “This computer · browser”라는 해제 가능한 기기를 만듭니다. 기존 v1 쿠키는 다시 연결해야 합니다. 긴 연결 토큰은 더 이상 표시되지 않으며 연결 폼에서도 사용할 수 없습니다. `remote code`는 한 번의 프리뷰 동안 `remote pair`의 숨겨진 별칭으로 유지됩니다. `remote code --rotate`와 `remote code --json`은 더 이상 쓸 수 없습니다.

브라우저 쿠키에는 HttpOnly와 SameSite=Strict가 적용됩니다. LAN 호스트 이름의 일반 HTTP에서는 Secure 쿠키를 사용할 수 없고 연결과 쿠키가 암호화되지 않습니다. 신뢰하는 네트워크를 사용하거나 직접 관리하는 프록시에서 HTTPS를 제공합니다. Origin 및 Fetch Metadata 검사는 유지됩니다. 마지막 접속 시각은 요청마다 메모리에서 갱신하고 최대 15분에 한 번 저장합니다. 유휴 기기는 쓰기를 발생시키지 않습니다.

상태에는 원격 접근 여부, 바인드 주소, LAN URL, 바인드 오류, 허용 호스트가 표시됩니다. 연결 코드는 상태에 표시되지 않습니다. 명령은 실행 중인 서비스가 필요하며 서비스를 자동으로 시작하지 않습니다. 연결할 수 없으면 `butler start`를 실행합니다.

## 포트 전달과 허용 호스트

WSL 포트 전달, 터널 또는 리버스 프록시가 다른 Host를 사용하면 이름이나 IP를 등록합니다. 앱에서는 **설정 → 보안**의 **터널·프록시용 허용 호스트**를 펼쳐 **호스트 이름**에 입력하고 **추가**를 누릅니다.

```bash
butler remote hosts add 192.0.2.10
butler remote hosts remove 192.0.2.10
```

허용 호스트에서도 기기 연결이 필요합니다. 포트 전달만으로 보안 관리 권한을 얻을 수 없습니다. 전달 도구와 보안은 직접 관리합니다.

## App 포트

현재 `butler config get app.port`는 값이 없다고 응답합니다. App 포트는 데이터 폴더의 `gateways/app.json` 안 `config.port`에 있으며, 변경은 재시작 후 적용됩니다. 실행 중인 서비스의 설정 파일을 직접 편집하지 않습니다.
