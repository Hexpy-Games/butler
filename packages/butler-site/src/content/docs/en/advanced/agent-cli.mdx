Butler Agent CLI is a command-line tool that installs and runs the Butler runtime without the desktop app. Install it with the install script or the standalone Agent archive. Its commands start and stop the service, check the installation, manage models and settings, and run the MCP server.

<Notice tone="info">
  If you use the Butler app, you do not need to install the CLI separately. The app manages its bundled Agent itself.
</Notice>

## Supported platforms

- Apple silicon Mac (`darwin-arm64`), Windows x64 and Linux x64 and arm64 (glibc) are supported.
- Intel Macs and musl-based Linux such as Alpine do not run it. Windows x64 is supported too.
- You need a release that publishes the native Agent archive (`butler-agent-<version>-<platform>.tar.gz`, or `.zip` on Windows).

## Install

To use Butler without the app, for example on a server or a remote computer, run the one-line install script. Butler is in preview, so download the script from a preview release and pass the same version with `--version`. Replace `<version>` with the newest preview on [GitHub Releases](https://github.com/Hexpy-Games/butler/releases), such as `0.1.0-preview.12`.

The install script works in this order.

<Steps>
  1. It checks the operating system and CPU, then downloads the archive and `butler-<version>-SHA256SUMS` for the latest release (or the version you specify).
  2. It verifies the checksum, then extracts the archive into a new version folder. The existing installation does not change until verification finishes.
  3. It points the `current` link to the new version and creates the `~/.local/bin/butler` executable.
  4. It checks the installation with `butler doctor --check installation`, then starts Butler.
</Steps>

It is safe to run the same command again. A version that is already installed is not extracted again, and the data folder is not touched. If Butler is already running, apply the new version with `butler restart`.

Add options after `sh -s --`.

```bash
curl -fsSL https://github.com/Hexpy-Games/butler/releases/download/v<version>/install.sh | sh -s -- --version <version> --no-start
```

| Option | Description |
| --- | --- |
| `--version X.Y.Z` | Installs this version instead of the latest release. You can also set it with the `BUTLER_VERSION` environment variable. |
| `--no-start` | Installs Butler without starting it. |
| `--modify-path` | Adds `~/.local/bin` to your shell configuration file when it is not in `PATH`. Without this option, the script only shows the line to add. |

Change the install folder with `BUTLER_AGENT_HOME` and the location of the `butler` executable with `BUTLER_BIN_DIR`. Both values must be absolute paths. The script does not run as root (set `BUTLER_ALLOW_ROOT=1` to allow it), and it stops if `~/.local/bin/butler` is a file other than Butler's executable. An older, pre-native executable is moved to `butler.previous`.

### Install locations

| Item | macOS | Windows | Linux |
| --- | --- | --- | --- |
| Install folder | `~/Applications/ButlerAgent` | `%LOCALAPPDATA%\Butler\agent` | `~/.local/share/butler/agent` |
| `butler` command | `~/.local/bin/butler` | `%LOCALAPPDATA%\Butler\bin\butler.exe` | `~/.local/bin/butler` |

Inside the install folder, each version gets a `<version>-<8-character hash>` folder. `current` points to the version in use and `previous` to the one before it. Only the 3 most recent old versions are kept (the version in use, the previous version and the running version are always kept), and `butler update` or `butler install` removes the rest. Data is stored in the data folder (default `~/.butler`), outside the install folder. The desktop app and the CLI use the same install layout.

### Manual install

If you cannot use the install script, extract the archive yourself. The archive is an install package that you extract into a new folder for each version.

  label="Operating system"
  items={[

    { value: "linux", label: "Linux" },

>
  <TabPanel value="macos">
    Use a `darwin-arm64` archive and the Bash steps below.
  </TabPanel>
  <TabPanel value="windows">
    On Windows, use the install script above. It downloads `butler-agent-<version>-windows-x64.zip`.
  </TabPanel>
  <TabPanel value="linux">
    Use a `linux-x64` or `linux-arm64` archive and the Bash steps below.
  </TabPanel>
</Tabs>

<Steps>
  1. On [GitHub Releases](https://github.com/Hexpy-Games/butler/releases), find a version that has the native Agent archive.
  2. Save the script below to a file (for example, `install-butler-agent.sh`) and change `VERSION`, `RELEASE` and `PLATFORM`.
  3. Run it with `bash install-butler-agent.sh`. It downloads the archive and `butler-<release>-SHA256SUMS`, verifies the checksum, then extracts the archive into a new version folder.
  4. The installation is complete when the final `version` and `doctor` commands finish without errors.
</Steps>

```bash
set -euo pipefail
VERSION=<version> # The exact release version, including the preview suffix, such as 0.1.0-preview.12.
RELEASE="$VERSION" # The release tag without v.
PLATFORM=darwin-arm64 # One of darwin-arm64, linux-x64 or linux-arm64.
ARCHIVE="butler-agent-${VERSION}-${PLATFORM}.tar.gz"
RELEASE_URL="https://github.com/Hexpy-Games/butler/releases/download/v${RELEASE}"
DOWNLOAD_DIR="$HOME/Downloads/butler-agent-${VERSION}"
INSTALL_ROOT="$HOME/.local/opt/butler-agent"
INSTALL_DIR="$INSTALL_ROOT/$VERSION"
export BUTLER_DATA="${BUTLER_DATA:-$HOME/.butler}"

mkdir -p "$DOWNLOAD_DIR" "$INSTALL_ROOT" "$BUTLER_DATA"
cd "$DOWNLOAD_DIR"
curl -fL --retry 3 -o "$ARCHIVE" "$RELEASE_URL/$ARCHIVE"
SUMS="butler-${RELEASE}-SHA256SUMS"
curl -fL --retry 3 -o "$SUMS" "$RELEASE_URL/$SUMS"
EXPECTED_SHA256="$(awk -v name="$ARCHIVE" '$2 == name { print $1 }' "$SUMS")"
test "${#EXPECTED_SHA256}" -eq 64
printf '%s  %s\n' "$EXPECTED_SHA256" "$ARCHIVE" | shasum -a 256 -c -

if [ -e "$INSTALL_DIR" ]; then
  printf 'Installation already exists; choose a new version directory: %s\n' "$INSTALL_DIR" >&2
  exit 1
fi
mkdir "$INSTALL_DIR"
tar -xzf "$ARCHIVE" -C "$INSTALL_DIR"
"$INSTALL_DIR/butler" --data "$BUTLER_DATA" version --json
"$INSTALL_DIR/butler" --data "$BUTLER_DATA" doctor --check installation --json
```

The archive contains these files.

- `butler-agent`: The executable.
- `butler`: A link to `butler-agent`. The commands on this page use `butler`.
- `resources/`: The resources needed to run.
- `native-agent-manifest.json`: The install manifest, with the version and SHA-256 information.

After a manual install, add the install folder to `PATH` so you can run `butler` without the full path. Put the line in your shell configuration file (such as `~/.zshrc`) to apply it in new terminals too.

```bash
export PATH="$HOME/.local/opt/butler-agent/X.Y.Z:$PATH"
butler version
```

## Commands

Run `butler --help` or `butler help schedule` for help in Korean and English. `butler --version` or `-V` shows the release version and build ID without a service or a data folder.

| Command | Purpose |
| --- | --- |
| `install --from ARCHIVE\|URL` | Installs a downloaded archive. For a first install, use the install script above. |
| `start`, `stop`, `restart` | Starts, stops or restarts the service. |
| `remote status`, `remote enable`, `remote disable`, `remote pair`, `remote devices`, `remote hosts add\|remove HOST` | Manage remote access |
| `status`, `open`, `doctor [--check NAME]`, `doctor --collect-logs` | Check status, open the browser, check the installation |
| `update --check`, `update --apply --yes` | Check for and install updates |
| `rollback`, `uninstall --yes` | Restore the previous version, uninstall |
| `startup enable\|disable\|status` | Manage start at login |
| `auth login\|logout\|status` | Manage model account connections |
| `model list\|status\|set MODEL` | View and choose models |
| `logs [--follow]` | Service logs |
| `schedule list\|show\|create\|update\|run\|delete` | Manage schedules |
| `mcp list\|add\|enable\|disable\|delete\|test` | Manage MCP server connections |
| `skills list`, `skills import PATH` | List and import skills |
| `config get KEY`, `config set KEY VALUE` | Read and change settings |
| `--version`, `-V` | Shows the release version and build ID. |
| `help`, `version` | Help, version |

Schedules run while the service is running. For the options of `schedule create` and `update`, see `butler help schedule`. `schedule list --status STATUS` filters by status, and `--include-deleted` also shows deleted schedules.

```bash
butler startup enable
butler auth login
butler model list
butler model set openai/gpt-6-luna
butler schedule list
butler mcp add --id docs --transport http --url https://example.com/mcp
butler skills import ./skill.zip
butler config set system.defaultModel openai/gpt-6-luna
```

Manage personalization and memory in the app. The CLI has no maintenance commands that edit the conversation, personalization or memory databases directly.

## Headless / WSL / server

In a terminal on the computer that runs the service, turn on remote access, then pair a device. Remote access is off by default.

```bash
butler start
butler remote enable
butler remote pair
```

On another computer, open `http://HOST:PORT` and enter the 8-digit code that `remote pair` shows. `HOST` is the address that reaches the server or WSL, and `PORT` is the port of the LAN URL that `remote enable` prints. A code works once, within 60 seconds, and is printed only in the local terminal. Keep the code private and do not save it in logs.

```bash
butler remote status --json
butler remote devices                      # List paired devices
butler remote devices --revoke DEVICE_ID   # Revoke one device
butler remote devices --revoke-all         # Revoke every device
butler remote hosts add 192.0.2.10
butler remote hosts remove 192.0.2.10
butler remote disable
```

If WSL port forwarding or a proxy presents a different host, add that name or IP to `allowedHosts`. For example, if you forward through the Windows host IP, run `butler remote hosts add WINDOWS_IP`. Set up port forwarding and the firewall separately. If the service is off, the commands tell you to run `butler start` and do not start it for you.

`remote status` shows whether remote access is on, the bind addresses, LAN URLs, bind errors for each address and allowed hosts. It does not show a code. `remote pair` runs until a device pairs or you press Ctrl-C, and issues a new code when the code expires. A device revoked with `remote devices` has to pair again. `remote code --rotate` and `remote code --json` no longer work. For the pairing steps, see [Remote access](/en/help/advanced/remote-access/).

Currently `butler config get app.port` cannot read the App port. The setting is `config.port` in `gateways/app.json` in the data folder, and a change applies after a restart. Stop the running service before you edit the configuration file.

`user.responseLanguage` sets the reply language (`ko` or `en`) separately from the interface language. `update.previews` controls preview updates (`true` or `false`), defaulting to `false`. The app and CLI share it when they use the same data folder. Check the preference with `status`.

```bash
butler config get user.responseLanguage
butler config set user.responseLanguage ko
butler config set update.previews true
butler status
```

Background browser runs when the App is not attached. It uses the installed App’s Electron, then Chrome for Testing if the App is absent or cannot start. `config.headlessBrowser` in `gateways/app.json` controls only the Chrome fallback (default `true`). `BUTLER_BROWSER_HEADLESS=on|off` overrides it; restart the agent after changes.

## Data and updates

Data is stored in `BUTLER_DATA` (default `~/.butler`). To use another folder, add `--data PATH`. The install folder and the data folder cannot overlap.

```bash
butler update --check
butler update --apply --yes
butler rollback --yes
```

An update installs the new version in a separate folder and restarts the running service. `rollback` returns to the previous version. `uninstall --keep-data --yes` removes only the installation, and `--purge-data` also deletes the data.

## Project folder

```sh
butler folder show
butler folder set /srv/projects
```

Select the folder Butler works in, separately from `--data` / `BUTLER_DATA`. Explicit selection grants the same consent as the App folder picker. The folder must exist, be a readable directory, and be outside DATA and protected home/system folders. Symlinks are resolved. A running gateway applies it to the next turn; a stopped service saves the same App database preference. Existing spaces keep their selected folders. `--data PATH` and `--json` are supported.
